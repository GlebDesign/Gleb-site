# Директива оркестратору: перестройка конвейера дизайна

Это изменение архитектуры процесса. Применить ко всем задачам «сверстать по референсу».

## 1. Новая структура ролей

**Было:** дизайнер (замеры) → верстальщик (код) → QA → приёмка → гейт.
**Стало: два агента вместо четырёх.**

### Агент «Производство» (один, неделимый)
Выполняет полный цикл в ОДНОЙ сессии, без передач другим агентам:
1. Снимает точные значения с референса (пипетка цветов, размеры/позиции в %, радиусы, типографика).
2. Сразу верстает по этим значениям.
3. Сам сверяет свой рендер с референсом: скриншот рядом со скриншотом, замер DOM по числам.
4. Сам чинит расхождения. Цикл «правка → скриншот → замер → фикс» повторяет до совпадения.
5. Работает по инструкции design-agent-instructions.md (референс измеряют, а не вдохновляются).

Запрещено разбивать этот цикл на подагентов или передавать «замеры» отдельно от вёрстки:
контекст замеров не переживает передачу, это источник возвратов.

### Агент «Аудит» (один проход в конце)
- Получает ТОЛЬКО готовый рендер + референс. Процесс производства ему не показывать —
  ценность аудита в незамыленном взгляде.
- Проверяет: совпадение с референсом по чек-листу (композиция, цвета пипеткой, отступы,
  типографика), адаптив на 375 / 1440 / 1600+, консоль без ошибок, все ссылки.
- Выдаёт список расхождений с координатами. НЕ чинит сам — возвращает список Производству.
- Один круг аудита. Если после второго круга остались расхождения — эскалация человеку
  с объяснением, а не третий круг.

## 2. Параллелизм

Блоки сайта — независимые задачи. Запускать N агентов «Производство» параллельно
по блокам, а не один конвейер последовательно. Общие для всех: файл дизайн-токенов
(цвета, шрифты, радиусы, отступы) — создаётся ДО параллельного запуска и передаётся
каждому как единственный источник стилей.

## 3. Гейты человеку

- Один гейт на сборку, не по блоку: показывать собранный сайт целиком (ссылка на превью
  + скриншоты «референс/результат» по каждому блоку парами).
- Формат сдачи каждого блока: что взято 1-в-1 / что подставлено из брендбука /
  отступления с причинами / запрошенные ассеты. Работа без этой секции не принимается —
  возвращается Производству без рассмотрения.
- Вопросы человеку копить и задавать пакетом, а не по одному.

## 4. Оценки сроков

- Запрещено давать прогнозы сроков «из головы» — модель не умеет предсказывать
  своё время, прогнозы всегда завышены страховкой.
- Вместо прогноза: сделать ПЕРВЫЙ блок, замерить фактическое время от старта до сдачи,
  экстраполировать на остальные с учётом параллелизма. Отвечать в формате:
  «первый блок занял X, осталось N блоков в M потоков → оценка Y».

## 5. Ассеты и блокеры

- Если для 1-в-1 нужен ассет (картинка, видео, экспорт из Figma) — честный плейсхолдер
  с пометкой TODO + запрос человеку с точным описанием, что и откуда экспортировать.
- Блокер не останавливает остальные блоки: параллельные агенты продолжают работу.

## Ожидаемый эффект
Убраны 2 из 3 передач контекста (главный источник возвратов), блоки идут параллельно,
человек отвечает один раз пакетом. Целевое время сборки сайта уровня «7 блоков» —
1–2 часа фактической работы вместо 5–7 прогнозных.
